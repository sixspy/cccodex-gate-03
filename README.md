# 闸口事件湖仓台

码头闸口扫描先落在贴源层，原文照收。建层员选定业务日，按事件字典把扫描收成明细层：进闸、出闸、倒箱。字典里没有的事件码、箱号不合法或时间读不出的扫描留在剔除清单，不进明细。

这里不管堆存量，只处理扫描事件怎么分层。

## 日切规则

贴源扫描落库到哪一个业务日，由全局唯一的日切规则说了算，各闸口不许各算各的。规则只能二选一：

| 规则 | 含义 |
|------|------|
| 落入自然日 | 按扫描时刻落入所在自然日 |
| 过线改记次日 | 扫描时刻到了日切线（含）就改记次日 |

- 规则写进日切设置后，当天不许再改；日切尚未钉住时，不许开始构建。
- 构建会带上当时知道的规则，和日切设置对不上就记「日切规则不符」，这批不入库。
- 改记日和记录日不一致的扫描进跨日队列；时刻空着的扫描不进队列。
- 跨日扫描定业务日用行锁排队，只放行与日切设置一致的那次，落选的一笔记「日切争用」。
- 日切列表看每条扫描的落入日、改记日、规则名、记录日；层详情会展开跨日前后的业务日。

### 日切接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/daycut/overview` | 日切设置、日切列表、日切争用记录 |
| PUT | `/api/daycut/settings` | 钉死日切规则：`{"rule": "natural"}` 或 `{"rule": "cutoff", "cutoff": "23:00"}` |
| POST | `/api/daycut/queue/<id>/settle` | 给跨日扫描定业务日：`{"biz_date": "2026-11-13"}` |
| POST | `/api/dates/<date>/build` | 构建需带 `{"rule": ..., "cutoff": ...}`，与设置不符整批不入库 |

## 种子数据

|--------|------|------|
| 2026-11-11 | 两条合法扫描 | 已收成进闸、出闸 |
| 2026-11-12 | 一条合法，一条未知事件码，一条坏箱号，一条跨日（时刻落在 11-13），一条过 23:00 日切线，一条时刻空着 | 还没构建 |

事件码只认 IN、OUT、RS。箱号是四位字母加七位数字。日切规则初始未钉住，要先到「日切」页钉死规则才能构建。
